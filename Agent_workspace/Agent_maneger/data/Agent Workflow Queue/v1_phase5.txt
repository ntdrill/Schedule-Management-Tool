## 設計方針

### 技術制約（資料準拠）
- **SwiftData** (`@Model` マクロ) を使用（`docs/readme/01_プロジェクト概要.md` 準拠）
- **Local First**: サーバー不要、データは端末内に保存
- **Watch Centric**: ユーザー状態の測定と簡易入力は Watch 単体で完結
- デバイス分担の詳細は Phase 6 で決定するため、Phase 5 ではデバイス非依存のモデル定義に留める

### v1 スコープ判定基準
- v1 コア機能（測定ON/OFF、対処行動の記録・評価、ログ閲覧、ローカル通知、期待状態の選択）に必要なクラスを **必須** とする
- v2 以降の機能（タイムラインUI、LLM連携、iCloud同期、社会的状態管理、危篤状態自動検知）に専用のクラスは **骨格のみ** または **スキップ** とする
- 未整備事項（U-01〜U-18）のうち実値未定義の定数は、仮値またはプレースホルダーとして定義する

### 分類ガイドライン
- **永続モデル（@Model）**: SwiftData で永続化するオブジェクト（状態履歴、実行記録、測定セッション等）
- **値型（struct）**: 計算中間値、一時的なスコア、フラグ群
- **列挙型（enum）**: 状態種別、優先度レベル、システムモード
- **プロトコル**: 共通インターフェース（状態オブジェクトの共通性など）

## Agent Workflow Queue (Phase 5: Schema Definition)

### セットアップ（Step 1〜4）

1. **Agent_Manager**: `Task_Management/02_Active` に親タスク `task_Phase5_Schema.txt` を作成する
2. **Symbol_Agent**: PRE-01（シンボル不一致）を修正する。`Agent_workspace/data_model_agent/業務/03_複合スナップショットの記述.txt` の P3-06 において `ꀀ` を `ꁀ` に修正し、修正内容を `task_Phase5_Schema.txt` に追記する
3. **Agent_Manager**: PRE-02（提案/ドラフト要素7件）の採否を判定し、`task_Phase5_Schema.txt` に判定結果を記録する
4. **Agent_Manager**: `task_Phase5_Schema.txt` 内で、Data_Model_Agent に「v1 スコープのスキーマ定義」を、Symbol_Agent に「整合性検証」をアサインする

### v1 スコープ分析（Step 5〜7）

5. **Data_Model_Agent**: `04_構造抽出.txt` を読み込み、v1 コア機能に必要なクラスを特定する。判定基準: v1 実装機能（測定モード管理、期待状態入力、対処行動と評価、データ収集と紐付け、通知）に直接関わるか
6. **Data_Model_Agent**: クラス候補25件を以下の3カテゴリに振り分ける:
   - **v1 必須**: v1 コア機能に直接必要（`@Model` として完全定義）
   - **v1 骨格**: v1 で存在は必要だがフィールドは最小限（`@Model` として骨格定義）
   - **v2 延期**: v1 では不要（定義スキップ、コメントで予約）
7. **Data_Model_Agent**: 変数候補164件と関数候補110件について、v1 必須クラスに属するもののみを対象として絞り込む。`task_Phase5_Schema.txt` にスコープ判定結果を追記する

### 永続モデル定義（Step 8〜11）

8. **Data_Model_Agent**: v1 必須クラスの SwiftData `@Model` 定義を作成する。各クラスについて以下を記述する:
   - クラス名（Swift 命名規則準拠）
   - `@Model` 宣言
   - プロパティ一覧（型、デフォルト値、Optional/Required）
   - `@Relationship` 宣言（他モデルとの関連）
   - Phase 4 のクラス番号（C-xx）との対応
9. **Data_Model_Agent**: v1 骨格クラスの最小限 `@Model` 定義を作成する（将来拡張用のプレースホルダーフィールドを含む）
10. **Data_Model_Agent**: 値型（struct）と列挙型（enum）の定義を作成する。Phase 4 の変数候補から型が Enum / struct と判定されたもの（V-79 reject_postpone, V-98 recovery_task_priority, V-99 measurement_session_quality, V-104 exception_route_selected 等）を対象とする
11. **Data_Model_Agent**: プロトコル定義を作成する。UserState / EnvironmentState / SocialState に共通する `StateObject` プロトコルなど、共通性があるクラス群のインターフェースを抽出する

### 整合性検証（Step 12〜14）

12. **Symbol_Agent**: Data_Model_Agent が作成したスキーマ定義を読み込み、Phase 4 の `04_構造抽出.txt` および `data/*.txt` のシンボル辞書と照合する
13. **Symbol_Agent**: 以下の整合性を検証する:
    - スキーマのプロパティ名がシンボル辞書の変数名と一致するか
    - Phase 4 のクラス間関係図（Section 4）がスキーマの `@Relationship` と整合するか
    - v1 必須に分類されたクラスが、v1 コア機能のスナップショット（Sn01〜20）をカバーしているか
    - 未整備事項（U-01〜U-18）のうちスキーマに影響するものが適切にプレースホルダー化されているか
14. **Symbol_Agent**: `Task_Management/02_Active` に `report_schema_validation_Phase5.txt` を作成し、検証結果（合格/不合格/要修正の項目リスト）を報告する。`task_Phase5_Schema.txt` に「整合性検証完了」を追記する

### 成果物作成（Step 15〜16）

15. **Data_Model_Agent**: Symbol_Agent の検証結果を反映し、`Agent_workspace/data_model_agent/業務/05_スキーマ定義.txt` に最終版を記述する。以下のセクションを含める:
    - v1 スコープ判定表（全25クラスの振り分け結果）
    - 永続モデル定義（`@Model` クラス一覧、フィールド、関連）
    - 値型・列挙型定義
    - プロトコル定義
    - ER 図（テキスト形式のエンティティ関連図）
    - 未整備事項への対処（仮値/プレースホルダーの一覧）
    - Phase 6 への申し送り事項（デバイス分担に影響する設計判断）
16. **Data_Model_Agent**: `task_Phase5_Schema.txt` に作業完了を追記する

### 完了処理（Step 17〜20）

17. **Agent_Manager**: 成果物（`05_スキーマ定義.txt`）と検証報告（`report_schema_validation_Phase5.txt`）を確認し、最終承認を行う
18. **Agent_Manager**: `Task_Management/02_Active` 内の `report_schema_validation_Phase5.txt` を `Task_Management/03_Completed` に移動する
19. **Agent_Manager**: 親タスク `task_Phase5_Schema.txt` を `Task_Management/03_Completed` に移動する
20. **Agent_Manager**: 完了したファイル群を `Task_Management/04_Archive/Phase5_Schema_[日付]/` にアーカイブする
