# 対処行動と場面の管理

## 概要

ユーザー状態エージェントは、ユーザーの状態に応じて適切な対処行動を提案・実行する責任を持ちます。本資料では、システムが管理する対処行動と、それらが必要になる場面（状態）の定義について説明します。

## データベース構造

### coping_actions テーブル（対処行動）

ユーザーが実行可能な対処行動・予防方法を定義します。

**主要フィールド:**
- `name` (TEXT, UNIQUE): 対処行動の名前
- `category` (TEXT): 分類（measurement, physical, nutrition, psychological, audio, tool, other等）
- `effectiveness_rating` (INTEGER): 効果評価（1-5）
- `ease_of_use_rating` (INTEGER): 手軽さ評価（1-5）
- `recommendation_rating` (INTEGER): おすすめ度（1-5）
- `description` (TEXT): 詳細説明

**登録データ数**: 78項目

### coping_scenarios テーブル（場面）

対処行動や予防が必要になる場面（症状・状態）を定義します。

**主要フィールド:**
- `name` (TEXT, UNIQUE): 場面の名前
- `category` (TEXT): 分類（physical, mental, cognitive, behavioral等）
- `severity_level` (TEXT): 軽度/中度/重度（mild/moderate/severe）
- `description` (TEXT): 詳細説明

**登録データ数**: 239項目

## カテゴリ分類

### 対処行動のカテゴリ

1. **measurement（測定・モニタリング系）**: SpO2測定、脈拍測定、パルスシフト、イベント境界測定など
2. **physical（身体・運動系）**: 太極拳、ヨガ、筋力トレーニング、人とゲーム・運動、日光浴、呼吸調整など
3. **nutrition（水分・栄養系）**: 水を飲む、電解質を取る、カフェインを摂る、カロリー管理、タンパク質摂取など
4. **psychological（心理・認知系）**: セーバリング、メタ認知、論理パズルの練習など
5. **audio（音・音楽系）**: 音楽を聴く、メルクリウスを聞く、閃光を聞く、子供の声を聞く、耳栓をするなど
6. **tool（ツール・環境系）**: リマインダーツール、アラーム、スクリーンタイムアプリ、ナイトガードなど
7. **other（その他）**: 心療内科や精神科に相談する、自己開示、道徳的観念が一致する人物/集団と交流するなど
8. **medical（歯科・医療系）**: 矯正歯科に通う、マウスピースを使用・メンテナンス、歯矯正など
9. **monitoring（チェックリスト・記録系）**: チェックリストで採点を行う、各種記録、測定など
10. **prevention（その他の具体的行動）**: 孤独な時間を減らす、回復ルーティンを予定化する、メタ認知でラベル付けするなど

## ユーザー状態エージェントの役割

### 1. 状態の監視と検知

ユーザー状態エージェントは、`coping_scenarios`テーブルに定義された場面（症状・状態）を監視し、該当する状態を検知します。

**検知方法:**
- センサーからの自動測定値（SpO2、脈拍、活動量など）
- チェックリストによる自己報告
- タスク実行時の状態記録
- 状態履歴の時系列分析

### 2. 対処行動の提案

検知された場面に応じて、`coping_actions`テーブルから適切な対処行動を提案します。

**提案ロジック:**
- 場面の`severity_level`に応じた優先度付け
- 対処行動の`effectiveness_rating`と`ease_of_use_rating`を考慮
- ユーザーの現在の状態と対処行動の前提条件のマッチング
- 過去の効果履歴に基づく推奨度の調整

### 3. 対処行動の実行支援

提案された対処行動の実行を支援します。

**支援内容:**
- リマインダーによる実行促進
- 実行前後の状態記録
- 効果の測定と評価
- 継続的な対処行動のスケジューリング

### 4. 状態と対処行動の関連付け

場面と対処行動の関連を管理し、効果的な対処パターンを学習します。

**関連付けの管理:**
- 多対多の関係テーブル（`coping_action_scenario_relations`）による管理
- 主要な対処法（`is_primary`フラグ）の識別
- 対処行動の組み合わせパターンの記録

## データソース

本資料で定義された対処行動と場面は、開発者の実体験に基づいて整理されたものです。

**参照資料:**
- `docs/開発者の実体験.txt` - リワークプログラム修了レポート
- `data/coping_actions.txt` - 対処行動データファイル（78項目）
- `data/coping_scenarios.txt` - 場面データファイル（239項目）

**データベース:**
- Supabase: `coping_actions`テーブル、`coping_scenarios`テーブル
- 登録スクリプト: `migrate_coping_data_to_supabase.py`

## 運用上の注意事項

1. **状態の多層性**: ユーザー状態は「現在の実状態」「状態の型/定義」「状態履歴」の3層で管理されるため、場面の検知はこれらを総合的に判断する必要があります。

2. **対処行動の優先順位**: 場面の`severity_level`が`severe`の場合は、即座に対処行動を提案する必要があります。`mild`の場合は、予防的な対処行動を提案します。

3. **対処行動の効果測定**: 対処行動実行前後の状態を記録し、`effectiveness_rating`の精度を向上させます。

4. **個人差の考慮**: 対処行動の効果は個人差が大きいため、ユーザーごとの効果履歴を記録し、パーソナライズされた提案を行う必要があります。

5. **再発予防**: 場面の検知だけでなく、再発パターン（孤立・モニタリング不足・負荷の押し切り）を早期に検知し、予防的な対処行動を提案します。

## 今後の拡張

1. **対処行動と場面の関連付けテーブル**: 多対多の関係を管理する`coping_action_scenario_relations`テーブルの作成とデータ登録
2. **効果履歴の記録**: 対処行動実行前後の状態変化を記録し、効果を定量化
3. **パーソナライズド推奨**: ユーザーごとの効果履歴に基づく推奨度の動的調整
4. **対処行動の組み合わせパターン**: 複数の対処行動を組み合わせた効果的なパターンの学習
5. **状態遷移モデル**: 場面から対処行動、対処行動から状態改善への遷移モデルの構築
