# ユーザー状態の多層的定義

ユーザー状態は単なるプロパティの集合ではなく、以下の三つの層で定義・管理されています。この多層構造により、リアルタイムの状態監視、理想状態の定義、過去の分析が可能になります。

## 1. 現在の実状態 (User State Object)

システムが認識する「現在のユーザー」そのものです。常に最新の状態を保持する単一のオブジェクトとして存在します。

*   **SubjectType**: `user`
*   **更新メカニズム**:
    *   **センサー自動更新**: スマートウォッチ等のデバイスから脈拍、血圧、活動量などをリアルタイムに反映。
    *   **ユーザー入力**: チェックリストや手動入力により、想起内容、行動、主観的な感覚を反映。
    *   **タスク実行**: タスクの開始・完了時に状態変化を記録。
*   **役割**:
    *   タスクの前提条件（Preconditions）チェックの対象となる。
    *   危篤状態検知や通知トリガーの判定基準となる。

## 2. 状態の型/定義 (State Schema)

「どのような状態であるべきか（またはあるべきでないか）」を定義する設計図です。

*   **役割**:
    *   **理想状態の定義**: 「標準状態」「作業開始可能状態」など、目指すべき状態の定義。
    *   **タスク効果の定義**: タスク実行によって期待される状態変化（Expected State）の記述。
    *   **前提条件の記述**: タスク実行に必要な状態要件の記述。
*   **構造**:
    *   状態オブジェクトのサブセットとして定義され、必要なフィールドのみを指定します（例：`{神経: "副交感優位", 脈拍: [60, 70]}`）。

## 3. 状態履歴 (State History Object)

過去の特定時点におけるユーザー状態のスナップショットです。

*   **生成タイミング**:
    *   タスク実行の直前（Actual State Before）
    *   タスク完了の直後（Actual State After）
    *   チェックリスト回答時
    *   定時記録（測定モード中など）
*   **役割**:
    *   **時系列分析**: 状態の変化トレンドを追跡し、危篤状態の予兆を検知する。
    *   **効果測定**: 期待状態（Expected）と実際の状態（Actual）を比較し、タスクの効果を評価する（Evaluation Result）。
    *   **エントロピー計算**: 状態の分散や変化量からユーザーエントロピーを算出する基礎データとなる。

---

## 状態オブジェクトの統合管理

これらのオブジェクトは、以下のように連携して機能します。

1.  **計画時**: 状態スキーマを用いて、タスクの「期待状態」と「前提条件」を定義する。
2.  **実行前**: 現在のユーザー状態オブジェクトを参照し、前提条件を満たしているか判定する。
3.  **実行時**: タスク開始時点のユーザー状態をスナップショットとして保存（状態履歴）する。
4.  **実行後**: タスク完了後のユーザー状態をスナップショットとして保存し、計画時の期待状態と比較評価を行う。
