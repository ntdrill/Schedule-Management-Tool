# 測定時間の集計と管理

過度な測定による疲労を防ぎつつ、必要なデータを確保するための時間管理。

## 1. 集計ロジック

### 1.1 実測定時間の算出
システムは、実行された「測定セッション」の実績時間に基づいて、日次の累積測定時間を計算します。

*   **集計対象**:
    *   `type=measurement_session` を持つ**実行オブジェクト** (Execution Object)。
    *   予定オブジェクトではなく、実際に記録された `actualStart` と `actualEnd` を使用します。
*   **計算式**:
    ```
    Daily Measurement Time = Σ (session.actualEnd - session.actualStart)
    ```
    *   `session` は、その日の 0:00 から 23:59 の間に終了した、あるいは進行中の測定セッション。
*   **中断の扱い**:
    *   ユーザーが一時停止を行ったり、システムが中断（`status=interrupted`）を検知した場合、その中断期間は測定時間から除外されます。
    *   実質的に測定が行われていた時間のみをカウントし、より正確な負荷評価を行います。

### 1.2 日次・週次集計変数
システムは以下の変数を常時更新し、しきい値判定に使用します。

*   **`measurement_time_daily`**:
    *   本日の累積測定時間（分または時間単位）。
    *   毎日 0:00 にリセットされます。
*   **`measurement_days_weekly`**:
    *   今週（月曜〜日曜など）の累積測定日数。
    *   「測定日」としてのカウント条件: その日の `measurement_time_daily` が一定値（例: 1時間）を超えた場合のみカウントするなど、実質的な稼働を評価します。

## 2. 推奨上限とアラート

### 2.1 日次制限 (Daily Limit)
1日あたりの測定時間が長すぎると、認知疲労や過覚醒のリスクが高まります。

*   **推奨範囲**:
    *   下限: `measurement_limit_daily_min` (6時間)
    *   上限: `measurement_limit_daily_max` (8時間)
*   **アラートロジック**:
    *   `measurement_time_daily` >= `measurement_limit_daily_max` となった時点で、システム通知を発火させます。
    *   **通知タイプ**: `measurement_limit`
    *   **メッセージ例**: 「本日の測定時間が推奨上限（8時間）に達しました。これ以上の測定は疲労の原因となります。非測定モードへの移行を推奨します。」

### 2.2 週次制限 (Weekly Limit)
週単位での休息日（非測定日）の確保を促します。

*   **推奨範囲**:
    *   下限: `measurement_days_weekly_min` (3日)
    *   上限: `measurement_days_weekly_max` (6日)
*   **アラートロジック**:
    *   **過剰アラート**: 週の途中で既に上限（6日）に達した場合、「今週はこれ以上測定日を増やさないようにしましょう」と提案。
    *   **不足アラート**: 週の後半（金曜・土曜など）で下限（3日）に満たない場合、「今週の測定日数が不足しています。週末に調整しますか？」と提案。
    *   **メッセージ例**: 「今週は休息を多めに取りましょう（過剰時）」

## 3. 測定モードの自動判定

### 3.1 予定オブジェクトによる判定
ユーザーがいちいち「測定開始ボタン」を押さなくても済むよう、カレンダー上の予定に基づいて測定モードを自動認識します。

*   **判定ロジック**:
    *   あるタスクが実行される時刻 `t` において、その時刻を包含する `type=measurement_mode` の予定オブジェクトが存在するかを確認します。
    *   `scheduledStart <= t <= scheduledEnd` (かつ `status != cancelled`) であれば、そのタスクは「測定モード内でのタスク」として扱われます。
*   **メリット**:
    *   ユーザーは「今日は9時から17時まで測定する」という予定ブロックを1つ置くだけで良い。
    *   その時間帯に行う個別のタスク（読書、運動など）は、自動的に測定対象として記録され、詳細なログが残る。
    *   予定外の時間帯（夜間など）にふと思い立ってタスクを行っても、測定モードの予定がなければ「非測定（簡易記録）」として扱われ、心理的負担が軽減される。

### 3.2 手動オーバーライド
*   予定オブジェクトがなくても、ユーザーが明示的に「今すぐ測定モードを開始」することは可能です（即時実行の測定セッションを作成）。
*   逆に、測定モードの予定時間内であっても、「一時的に測定をオフにする（プライバシーモード）」ことも可能です。
