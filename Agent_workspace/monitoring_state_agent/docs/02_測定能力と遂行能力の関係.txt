# 測定能力と遂行能力の関係

本ドキュメントでは、測定能力（Measurement Capability）と遂行能力（Executive Function）の相互依存関係、およびシステム内部での評価・計算ロジックについて詳述する。

## 1. 測定能力 (Measurement Capability) の詳細定義

### 概念的定義
測定能力とは、単にセンサーデータを読み取る能力ではなく、**自身および他者の状態を客観的に観測し、確定させるメタ認知能力**を指す。これはカオス的な内部状態（ユーザー分散が高い状態）に対して、観測という行為によって波動関数を収縮させ、状態を確定させる物理的な作用としてモデル化される。

### システム上の表現
-   **変数**: `user_measurement_capability` (ꀳ)
-   **データ型**: スカラ値 (0.0 - 1.0)
-   **構成要素**:
    1.  **感覚受容の精度**: 身体感覚（Interoception）を正確に知覚できるか。
    2.  **言語化能力**: 感覚を「疲れている」「焦っている」等の記号に変換できるか。
    3.  **持続的注意**: モニタリング行為を継続するウィルパワー。

## 2. 遂行能力 (Executive Function) との動的関係

本システムでは、「測定可能な状態が遂行能力を保証する」という**アンカー仮説**を採用している。

### 決定論的モード (Deterministic Mode)
-   **条件**: `is_measurement_state_active` (ꀚ) が `True` の場合。
    -   具体的には、`user_measurement_capability` > `threshold_measurement_capability_for_monitoring` (ሤ) を満たしている状態。
-   **挙動**: ユーザーは計画されたタスクを意図通りに実行できると仮定される。タスク完了率は高く、予定と実績の乖離は最小化される。
-   **システム処理**: タスクキューの順次実行を促し、詳細なログ記録を行う。

### 確率的モード (Probabilistic Mode)
-   **条件**: 測定能力が閾値を下回り、測定状態が維持できなくなった場合。
-   **挙動**: ユーザーの行動は確率的になる。タスクを実行するか、先延ばしするか、全く別の行動をとるか（例：過集中、逃避）が予測不可能になる。
-   **システム処理**:
    -   `probability_of_recovery` (ꀤ) を計算し、元の状態に戻れる確率を監視する。
    -   複雑なタスクの提案を停止し、リカバリータスク（単純な呼吸法や片付け）のみを提示する。

## 3. 脳の報酬系と決定因子

測定能力は静的な能力ではなく、生物学的・環境的要因によって刻々と変動する。

### 脳の報酬系 (Reward System)
最も影響の大きい因子として仮定されている。
-   **メカニズム**: ドーパミン作動性ニューロンの活動レベルが、測定（モニタリング）という報酬の遅延を伴う行為の持続可能性を決定する。
-   **影響**: 報酬系が機能不全（過剰な即時報酬への依存、または枯渇）に陥ると、測定能力は著しく低下する。

### その他の決定因子
1.  **環境エントロピー (Environment Entropy)**:
    -   環境分散 (`calc_user_variance` (ꀆ) の入力) が高いと、ユーザーの認知リソースが外部刺激処理に奪われ、内部観測のリソースが枯渇する。
    -   関係式: $Capability \propto \frac{1}{Entropy_{env}}$
2.  **生理的状態**:
    -   自律神経バランス (`autonomic_nerve_balance` (ꀃ)) の崩れや、血糖値の乱れ（`hard_carbohydrate_intake_flag` (ᐌ)）は測定能力を低下させる。

## 4. システム内部での計算プロセス

システムは以下のフローで測定能力と遂行能力を評価・更新する。

### 入力データ
-   **環境センサー**: 室温、騒音、CO2濃度、オブジェクト数 (`temp_object_counts` (ꀯ))
-   **生体センサー**: 脈拍変動、活動量
-   **ユーザーログ**: 過去のタスク実行履歴、チェックリスト回答

### 処理ロジック (Transforms)
1.  **ユーザー分散の算出**:
    `calc_user_variance` (ꀆ) を用いて、環境エントロピーからユーザーの内部状態の分散（不安定さ）を推定する。

2.  **測定能力の算出**:
    `calc_measurement_capability` (→) を実行。
    $$Capability = f(Variance_{user}, Biology_{factor}, Reward_{status})$$

3.  **遂行能力の有効性判定**:
    `judge_executive_function_validity` (↧) を実行。現在の測定能力が閾値を超えているかを判定し、システムモード（決定論的 vs 確率的）を切り替える。

### 出力・作用
-   **変数更新**: `executive_function_level` (ꀖ) および `user_measurement_capability` (ꀳ) の更新。
-   **ドロップアウト予測**: `predict_measurement_dropout` (↫) により、近い将来の測定放棄リスクを算出。

## 5. 命綱としての機能と介入

測定は、カオス（確率的状態）に陥ったユーザーを秩序（決定論的状態）へと引き戻す唯一の「命綱」である。

### フェイルセーフ機能
遂行能力が失われたと判定された場合、システムは「タスク遂行」の支援から「測定能力の回復」へと優先順位を切り替える。

### 介入シナリオ
1.  **環境介入**:
    測定能力低下の原因が環境エントロピーにあると判断された場合、「まず机の上を片付けましょう」「換気をしましょう」といった、環境負荷を下げるアクションを提案する。
2.  **生理的介入**:
    自律神経の乱れが原因の場合、「深呼吸」や「水分摂取」を促す。

この介入により、ユーザーは再び「測定可能な状態」を取り戻し、遂行能力を回復させることができる。
