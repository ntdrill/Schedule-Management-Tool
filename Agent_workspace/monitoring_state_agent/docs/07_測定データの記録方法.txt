# 測定データの記録方法

本システムでは、ユーザーの入力負荷を最小限に抑えつつ、将来の分析に必要なデータを確保するために、**「センサーによる常時記録」**と**「ユーザー入力による選択的記録」**を組み合わせたハイブリッド戦略を採用する。

## 1. 記録戦略の基本方針（ハイブリッド・モデル）

### 常時記録 (Continuous Recording)
-   **対象**: センサーから自動取得可能な全てのデータ。
-   **原則**: タスクの有無やユーザーの意図に関わらず、システムが稼働している限り（特に測定モード中は）常にバックグラウンドで記録し続ける。
-   **目的**:
    -   ユーザーの操作負荷ゼロで客観的データを蓄積する。
    -   将来的な分析（相関発見、ベースライン確立）のためのデータを確保する。
    -   「あの時のデータがあれば」という事後的な後悔を防ぐ。

### 選択的記録 (Selective Recording)
-   **対象**: ユーザー入力が必要な主観的データ（気分、感覚、意図など）。
-   **原則**: 実行するタスクの **`expectedState`（期待される状態）で明示的に指定されたフィールドのみ** をユーザーに尋ねる。
-   **目的**:
    -   入力負荷を劇的に低減し、継続率を高める（「全部入力する」疲れを防ぐ）。
    -   そのタスクにとって本質的に重要な変化のみに焦点を当てる。

---

## 2. センサー自動取得 (Automatic Sensor Data)

### 取得データ項目
`StateObject` の該当フィールドに自動マッピングされる。
-   **バイタル**: 心拍数 (bpm), 脈拍変動 (HRV), 血圧 (mmHg), 酸素飽和度 (SpO2)
-   **活動**: 歩数, 活動量 (Active Energy), 睡眠ログ (Sleep Analysis)
-   **環境**: 室温, 湿度, CO2濃度, 騒音レベル (dB), 照度 (lux)

### 測定モード中の挙動と技術的制約
-   **理想的な挙動**: バックグラウンドで高頻度（例: 1分間隔）またはリアルタイムにストリームデータを収集する。
-   **プラットフォーム制約への対応**:
    -   **iOS/watchOS**: `HealthKit` のバックグラウンド更新制限を考慮し、重要な変化時のみ記録するか、定期的な「スナップショット」として保存する。
    -   **省電力モード**: 測定品質スコア (`current_measurement_quality_score`) に反映させつつ、サンプリングレートを動的に調整する。

### データソース識別
-   `StateObject.source` = `'auto_sensor'`

---

## 3. ユーザー入力 (User Input)

### インターフェースの種類
1.  **タスク完了時ダイアログ**:
    -   タスク終了直後に提示。
    -   `expectedState.After` に基づく必要最小限の質問（例: 「リラックスできましたか？ (Yes/No)」）。
2.  **チェックリスト**:
    -   定期的（起床時、就寝前）またはトリガー条件（測定モード開始時）で提示。
    -   複数の状態変数をまとめて確認するセット。
3.  **手動記録 (Manual Entry)**:
    -   ユーザーが任意でダッシュボードから入力。
    -   突発的な症状（痛み、不安）や気づきの記録。

### 選択的記録のロジック例
**シナリオ**: 「太極拳」タスクを実行する場合
-   **タスク定義 (`TaskTemplate`)**:
    -   `expectedStateAfter`: `{ "神経": "副交感優位", "筋肉": "弛緩" }`
-   **記録時の挙動**:
    -   システムは「神経状態」と「筋肉の緊張度」**のみ**を質問するダイアログを生成する。
    -   「栄養」や「社会的状態」などは、このタスクの主目的ではないため質問しない（スキップする）。
    -   ※ただし、センサーデータ（脈拍等）は裏で自動的に記録されている。

### データソース識別
-   `StateObject.source` = `'manual'` (手動), `'task_completion'` (タスク完了時), `'checklist'` (チェックリスト)

---

## 4. 記録プロセス（タスク実行フロー）

タスク実行時には、以下の2段階で状態記録（スナップショット保存）が行われる。

### Phase 1: 開始時記録 (Pre-Task)
1.  **トリガー**: ユーザーがタスクの「開始」ボタンを押す。
2.  **センサー取得**: その瞬間の最新センサーデータを取得。
3.  **ユーザー入力**: `expectedState.Before`（前提条件）にある項目について、現在の状態を尋ねる（オプション）。
    -   例: 「現在、空腹ですか？」
4.  **保存**: `StateObject` を生成し、`TaskInstance.stateBefore` にIDを記録。

### Phase 2: 終了時記録 (Post-Task)
1.  **トリガー**: ユーザーがタスクの「完了」ボタンを押す。
2.  **センサー取得**: その瞬間の最新センサーデータを取得。
3.  **ユーザー入力**: `expectedState.After`（目標状態）にある項目について、結果を尋ねる。
    -   例: 「神経は落ち着きましたか？」
4.  **保存**: `StateObject` を生成し、`TaskInstance.stateAfter` にIDを記録。
5.  **評価**: `stateBefore` と `stateAfter` の差分、および `expectedState` との乖離を計算し、`evaluationResult` を生成する。

---

## 5. データモデル上の表現

記録されたデータは `StateObject` として統一的に管理される。

```typescript
interface StateObject {
  id: string;
  timestamp: Date;
  
  // 記録のコンテキスト
  source: 'manual' | 'task_completion' | 'checklist' | 'auto_sensor';
  isMeasured: boolean; // 測定モード中の記録か
  
  // データの信頼性
  confidence?: number; // 主観的確信度 (0.0-1.0)
  evidence?: string;   // 根拠 (例: "Apple Watch Series 8")
  
  // 状態データ (User, Environment, Social)
  // ... (各フィールド)
}
```
