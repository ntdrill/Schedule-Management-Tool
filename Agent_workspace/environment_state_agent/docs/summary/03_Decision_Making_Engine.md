# 意思決定エンジン (Resource Arbitration)

## 1. 概要
環境状態エージェントの中核となる、リソース調停レイヤー (`Arbitration Layer`) のロジックです。
「いつ、何を掃除すべきか」という問いに対し、感情ではなく**「機会費用（Opportunity Cost）」の最小化**という経済学的・数理的アプローチで最適解を導出します。

## 2. 評価関数

システムは「現在の汚れ」ではなく、「未来の損失」を評価基準とします。

### 2.1 限界効用 (Marginal Utility)
あるタスクを実行することによる「利得」を、**「今やらなかった場合に増えるペナルティの量（損失回避量）」**として定義します。

$$
MU = \text{Penalty}(S_{t+1}^{ignored}) - \text{Penalty}(S_{t}^{current})
$$

- 指数関数的に悪化するカビ（Mold）は、放置すると次のステップでペナルティが激増するため、$MU$ が極めて高くなります。
- 線形に悪化する埃（Dust）は、放置してもペナルティ増加が一定であるため、$MU$ は低く保たれます。

### 2.2 投資対効果 (ROI)
単位コストあたりの効用を計算します。

$$
ROI = \frac{MU}{\text{Cost}(Time + Energy)}
$$

---

## 3. 調停ロジック (Arbitration Logic)

ユーザーのリソース（時間・体力）は有限であるという前提の下、「リソース制約付きナップサック問題」としてタスク選択を行います。

### 3.1 アルゴリズム
1.  全環境変数について、将来予測（`predict_value`）を行い、放置した場合のリスクを計算する。
2.  各変数の介入コスト（`calculate_intervention_cost`）を見積もる。
3.  全タスク候補を $MU$（または $ROI$）の高い順にソートする。
4.  ユーザーの空きリソース（`UserResource`）の上限に達するまで、上位のタスクを採用（`Accepted`）する。
5.  あふれたタスクは却下（`Rejected` / 先送り）とする。

### 3.2 導出される戦略
このロジックにより、システムは自動的に以下の戦略を振る舞いとして示します。

*   **カビ (Mold) への対応**:
    *   コストが高くても最優先でリソースを割り当てる。
    *   理由：今やらないと将来コストが破綻するため（機会費用が最大）。
*   **散らかり (Clutter) への対応**:
    *   リソースが逼迫している時は、合理的に切り捨てる。
    *   理由：放置してもリスクが爆発しないため。
*   **埃 (Dust) への対応**:
    *   ある程度溜まるまで待つ（規模の経済）。
    *   理由：頻繁な介入は固定コストの無駄遣いとなり ROI が下がるため。

---

## 4. 最適介入閾値シミュレーション

`optimization_simulation.py` による検証結果では、各変数の特性に応じた「最適介入閾値（どのくらい汚れたらやるべきか）」が導出されています。

*   **Linear (Dust)**: 閾値 `0.4 - 0.6`。ある程度溜めるのが正解。
*   **Exponential (Mold)**: 閾値 `0.1`。発生の兆候が見えたら即座に叩くのが正解。
*   **Sigmoid (Air)**: 閾値 `0.8` (変曲点付近)。限界ギリギリまで耐えてから換気するのが正解。

システムはこの閾値を動的に調整しながら、ユーザーに指示を出します。
