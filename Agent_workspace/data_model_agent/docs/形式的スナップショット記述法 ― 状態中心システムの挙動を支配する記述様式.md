### タイトル案
**「形式的スナップショット記述法 ― 状態中心システムの挙動を支配する記述様式」**

### 1. 目的
本資料は、状態中心システムにおける挙動記述を、自然言語や図解よりも厳密で再利用可能な形式に統一することを目的とする。特に「入力元」「出力先」「副作用」「依存関係」を一文の論理式として明示し、データモデル設計の基礎単位とする。

### 2. 形式的記述が支配的である理由
形式的記述は、(1)解釈の揺れを排除できる、(2)論理的整合性の検証が可能、(3)実装詳細を捨象して本質だけを抽出できる、という点で他の表現手段に対して支配的である。これは「仕様の確定」「矛盾の早期発見」「抽象化の正確性」に直接寄与する。

### 3. 最小構文と記述ルール
スナップショットは「1文の論理式」で記述し、定義済みシンボル以外を使用しない。未定義記号が必要な場合は `?_n` を用いる。関数は引数を明示し、出力は必ず `⟼` で束縛する。副作用は更新先を明示する。

### 4. 記述に含めるべき情報
- 入力元（センサー、ユーザ入力、辞書、時刻など）
- 変換（関数・演算子）
- 出力先（変数束縛・フィールド更新）
- 副作用（状態更新・通知生成・記録追加）
- 依存関係（条件分岐の根拠）

### 5. 代表的パターン
A. 状態更新 → 乖離算出 → 判定  
B. 判定 → 予定生成 → 実行記録 → 評価  
C. 評価 → 再判定 → 収束確認  
各パターンは「一文式」に圧縮し、変数名の一貫性で再利用可能にする。

### 6. 設計プロセスへの適用
スナップショットを多数記述し、そこから状態オブジェクト、変換関数、リレーションを帰納的に抽出する。図解やクラス設計は、スナップショット集合を根拠にした二次成果物とする。

### 7. 運用上の注意
- 「曖昧な動詞」を禁止する（例: 管理する、評価する、記録するだけでは不足）
- すべての関数に入力と出力を持たせる
- 実行結果の保存先を必ず指定する
