## 1. v1 スコープ判定表

判定基準:
- v1 コア機能: 測定ON/OFF、対処行動の記録・評価、ログ閲覧、ローカル通知、期待状態の選択
- v2 以降: タイムラインUI、LLM推論、iCloud同期、社会的状態管理、危篤閾値自動検知、CO2詳細センサー、代替行動自動提案

#### 2.1.1 UserState（C-01）

資料準拠: ꀴ, Sn01〜19, P3-01,03

ユーザーの現在状態。センサーデータと主観入力を統合保持する中心エンティティ。
v1 ではシングルトン的に「最新状態」を1レコードとして保持し、変化時に UserStateHistoryRecord へスナップショットを追記する。

```swift
@Model
final class UserState {
    var id: UUID = UUID()
    var timestamp: Date = Date()

    // --- センサーデータ（V-05, V-06）---
    var heartRateBpm: Double?           // ꀵ 心拍数 (bpm)
    var hrvMs: Double?                  // ꀶ 心拍変動 (ms)

    // --- 主観入力（V-07〜V-10）---
    var valenceScore: Double?           // ꀷ 快-不快 [1-5]
    var arousalScore: Double?           // ꀸ 覚醒度 [1-5]
    var focusScore: Double?             // ꀹ 集中度 [1-5]
    var fatigueScore: Double?           // ꀺ 疲労度 [1-5]

    // --- 測定状態フラグ（V-47）---
    var isMeasurementStateActive: Bool = false  // ꀚ

    // --- v1 骨格フィールド ---
    var measurementCapability: Double?  // ꀳ 測定能力スコア (v1骨格)
    var measurementCapabilityStatusRaw: String = "normal"
        // MeasurementCapabilityStatus の rawValue 格納

    // --- Relationship ---
    @Relationship(deleteRule: .cascade, inverse: \UserStateHistoryRecord.userState)
    var historyRecords: [UserStateHistoryRecord] = []

    init() {}
}
```

#### 2.1.3 ExecutionRecord（C-05）

資料準拠: ─_exec, Sn01,19, P3-01,02

対処行動の実行記録。行動の開始/終了時刻、前後の状態スナップショット、評価結果を保持する。

```swift
@Model
final class ExecutionRecord {
    var id: UUID = UUID()
    var actionTemplateId: String = ""
    var actionName: String = ""
    var startTimestamp: Date = Date()
    var endTimestamp: Date?

    // --- 主観評価（Sn19: ꃠ phase1_effectiveness_score）---
    var userRating: Double?             // [1-5] ユーザー主観効果評価

    // --- Relationship ---
    var measurementSession: MeasurementSession?

    @Relationship(deleteRule: .nullify)
    var stateBefore: UserStateHistoryRecord?    // 行動前スナップショット

    @Relationship(deleteRule: .nullify)
    var stateAfter: UserStateHistoryRecord?     // 行動後スナップショット

    @Relationship(deleteRule: .cascade)
    var evaluationResult: EvaluationResult?

    // delta_result は stateAfter - stateBefore から算出可能なため
    // v1 では永続プロパティとせず、算出プロパティとして実装する
    // var deltaResult: DeltaResult? → computed or transient

    init(actionTemplateId: String, actionName: String) {
        self.actionTemplateId = actionTemplateId
        self.actionName = actionName
    }
}
```

|---|---|
| UserStateHistoryRecord と ActualStateSnapshot の統合 | 構造が類似。recordTypeRaw で区別して単一モデルにする案。ただし評価用途の独立性を維持するため、Phase 6 で最終判断。 |

### 8.3 v1 → v2 拡張パス

v2 移行時にスキーマ破壊変更を最小化するための設計指針:

1. **EnvironmentState (C-02)**: v2 でフィールドを追加するのみ（moldRisk, dustAccumulation 等）。SwiftData のマイグレーションで対応可能。
2. **SocialState (C-03)**: v2 で新規モデルとして追加。既存モデルへの影響なし。
3. **ScheduledEvent (C-04)**: v2 で expected フィールド、recurrenceRule 等を追加。
4. **v2 専用モデル**: C-11〜C-17, C-19, C-21〜C-25 はすべて新規追加。既存スキーマに非破壊的に追加可能。
5. **Enum 拡張**: v2 延期の enum（RecoveryTaskPriority 等）は新規追加のみで既存 enum への影響なし。

### 8.6 特記事項

1. **StateVector の表現**: ExpectedStateSchema.stateVectorJson と ActualStateSnapshot の状態ベクトルは v1 では JSON 文字列としてエンコード。v2 で構造化する際の互換性を考慮し、キーは英語スネークケースで統一する（例: `{"valence": 3.0, "arousal": 4.0, ...}`）。

2. **SwiftData マイグレーション戦略**: v1 → v2 のスキーマ変更は「フィールド追加」と「新規モデル追加」のみで構成される。SwiftData の軽量マイグレーションで対応可能な設計としている。

3. **EvaluationResult の汎用性**: v1 では matchScore（0.0-1.0）のみを定量的評価とし、detailEvaluationJson に自由形式の詳細を格納する。v2 で構造化された評価スキーマに移行する際、JSON からの変換パスを用意する。
