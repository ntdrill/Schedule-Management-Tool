## 提案/ドラフト
### 1) 既存シンボルへの対応付け（no-op 想定）
以下の候補は既存シンボルと意味が重複するため、**新規発行せず既存参照**とする提案。

- `Calc_Measurement_Capability(...)` → `calc_measurement_capability`
- `Validate_Continuity(...)` → `validate_measurement_continuity`
- `Calc_Discrepancy(Sub, Obj)` → `calc_subjective_objective_discrepancy`
- `Sensor_Habituation` → `sensor_habituation_factor`
- `CMQS` 関連 → `current_measurement_quality_score` + `calc_measurement_reliability` の組み合わせで代替可能
  - ※ `calc_measurement_reliability` は `data/transforms.txt` に存在

### 2) 新規シンボル提案（不足分）
#### Group E: 変換・関数
- **name**: `eval_response_latency`
  - **description**: 介入通知からの反応時間を評価し、精神運動制止/過速/無反応のフラグを出力する関数
  - **source**: UC-M06（反応潜時評価）
  - **value_type**: json（判定結果の構造化を想定）

- **name**: `judge_system_mode_by_capability`
  - **description**: 測定能力スコアを入力し、決定論モード/確率的モードを判定する関数
  - **source**: UC-M08（System Mode Update）
  - **value_type**: string（"deterministic" | "probabilistic" を想定）

#### Group D: コンテナ・構造（登録先未整備のため保留）
- **name**: `measurement_session`
  - **description**: 測定セッションの予定オブジェクト（type="measurement_session"）
  - **source**: UC-M01/UC-M02
  - **note**: 登録先の確定後にシンボル化
