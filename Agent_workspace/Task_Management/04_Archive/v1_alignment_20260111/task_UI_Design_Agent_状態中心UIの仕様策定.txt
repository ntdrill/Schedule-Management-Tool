# タスク: 状態中心UIの仕様策定

作成日: 2026/01/01
担当: UI_Design_Agent
ステータス: アーカイブ（v2以降に延期）

## 注意
**本タスクはv2以降の機能を含むため、v1では実装対象外です。**
v1では測定モード管理UI・対処行動記録UIのスナップショット策定のみを行います。

## 目的
`docs/UIとUXに関する決定` および `docs/データモデルに関する決定` に記載された方針に基づき、実装可能なUI仕様を策定する。
特に、UIを「状態の関数」として捉え、シンボルを用いた形式記述（スナップショット）によってロジックとの整合性を担保する。

## 要件（v2以降）
1. **タイムライン表示** ※v2以降
   - DAWライクな並列トラック表示（測定モード、状態ブロック）。
   - ドラッグ＆ドロップ操作の仕様（※初期実装はクリックベースでも可）。
2. **状態可視化** ※v2以降
   - ユーザー状態・環境状態・社会的状態の直感的な表現。
   - 「アスタリスク型」や「色相変化」によるサマリー表示の仕様。
3. **インタラクション** ※v1対象
   - 状態確認通知（Yes/No）のフロー。
   - 詳細情報の段階的開示（タップで展開）。

## 追加要件: UIスナップショットの記述
画面図だけでなく、UIの振る舞いをシンボルで形式的に記述すること。
- **View関数**: どの状態 (`State`) がどのコンポーネント (`Component`) に変換されるか。
  - 例: `State(User) ⟼ Graph(Asterisk)`
- **Action遷移**: どの操作 (`Input`) がどの状態遷移 (`Update`) を引き起こすか。
  - 例: `Click(Confirm) ≫ Update(State)`
- 必要に応じて、UIコンポーネントを表すシンボルの追加提案を行うこと。

## 成果物
- 画面構成図（ワイヤーフレーム相当のテキスト記述またはSVG）。
- **UIスナップショット記述書**（シンボルによる論理定義）。
- 必要なAPIエンドポイントの要件定義（Backend実装用）。
