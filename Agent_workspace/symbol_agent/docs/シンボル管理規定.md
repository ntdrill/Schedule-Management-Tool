# シンボル管理規定 (Symbol Management Regulation)

## 1. 目的と適用範囲
本規定は、システムを形式的に記述するための「言語」である**シンボル（記号）**の定義、登録、管理に関するルールを定める。
Symbol_Agentは本規定に基づき、**記号接地（Symbol Grounding）**の責任を負い、概念と実装の一貫性を保証する。

## 2. シンボルの定義
シンボルとは、単なる識別子ではなく、以下の3要素を統合した情報単位である。
1.  **記法 (Notation)**: Unicode空間上で一意のコードポイント（形状）。
2.  **識別子 (Identifier)**: プログラム上で扱われる一意の名称（英語）。
3.  **接地 (Grounding)**: その記号が指し示す現実の物理量、状態、または論理的機能の定義。

## 3. 分類カテゴリ（意味論的分類）
シンボルは、その役割（品詞）に応じて厳格に分類され、視覚的に区別可能なUnicodeチャートが割り当てられる。

| グループ | 意味的役割 | Unicode範囲 | 性質・メタファー |
| :--- | :--- | :--- | :--- |
| **A** | **物理定数** (Constants) | `U+1401`〜 (Canadian) | **不変・基盤**。<br>自然界や物理法則に基づく固定値。 |
| **B** | **設定・閾値** (Settings) | `U+1200`〜 (Ethiopic) | **律法・制約**。<br>システムやユーザーが定めたルール。 |
| **C** | **動的状態** (Variables) | `U+A000`〜 (Yi) | **実体・現在**。<br>時間と共に変化する状態のコンテナ。 |
| **D** | **構造・枠** (Structure) | `U+2500`〜 (Box) | **骨格・接続**。<br>データを保持する配列やキュー。 |
| **E** | **作用・変換** (Functions) | `U+2190`〜 (Arrows) | **ベクトル・変化**。<br>入力から出力への計算や遷移。 |

## 4. ライフサイクル管理

### 4.1 提案 (Proposal)
*   **要件**: 新たなシンボルの提案は、単に「IDが欲しい」だけでなく、**「その概念がシステムに必要である論理的根拠」**を伴わなければならない。
*   **提出先**: `Task_Management/01_Proposals/`
*   **審査基準**:
    *   **一意性**: 既存の概念と重複していないか。
    *   **接地性**: その記号は何を測定・計算するものか明確か。
    *   **形式性**: 数式の中で矛盾なく使用できるか。

### 4.2 採番と登録 (Registration)
*   **担当**: Symbol_Agent
*   **責務**: 適切なカテゴリ（チャート）を選択し、システムの「辞書」に恒久的に登録する。
*   **衝突解決**: 提案された記号が既存定義と衝突する場合、**既存定義を優先（維持）**し、提案に対して**新しい記号を発行**して解決する。既存定義の上書き変更は原則禁止とする。
*   **登録先**:
    *   **Primary（正本/Master）**: シンボルデータベース (`Supabase/symbols`)
    *   **Replica（ミラー）**: システム定数/変数/変換ファイル (`data/*.txt`)

### 4.3 不変性と廃止
*   **不変性**: 一度意味（Grounding）を与えられた記号は、その意味を変更してはならない。意味が変わる場合は、新しい記号を発行する。
*   **廃止**: 使用されなくなった記号は「廃止（Deprecated）」とし、そのコードポイントは永久欠番とする（歴史的記録の保全）。

## 5. データベース運用（Symbol Bank）
