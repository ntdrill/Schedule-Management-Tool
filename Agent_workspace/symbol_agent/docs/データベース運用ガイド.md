# データベース運用ガイド (Database Operation Guide)

## 1. 概要
本ガイドは、Symbol_Agentが管理するシンボルデータのデータベース（Supabase）への移行および運用手順を示す。

## 2. 接続情報
*   **プラットフォーム**: Supabase
*   **認証情報**: `Agent_workspace/symbol_agent/key/supabase_1.txt` を参照
    *   `SUPABASE_URL`
    *   `SUPABASE_KEY`

## 3. テーブル設計
シンボル管理の中核となる `symbols` テーブルの定義。

### 3.1 symbols テーブル
| カラム名 | 型 | 制約 | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | UUID | PK | レコード固有ID |
| `char` | TEXT | UNIQUE | Unicode文字（シンボル本体） |
| `name` | TEXT | UNIQUE | 変数名・定数名（英語） |
| `category` | TEXT | NOT NULL | A〜Eの分類コード |
| `description` | TEXT | | 日本語の説明 |
| `value_type` | TEXT | | 型情報（float, int, json等） |
| `default_value`| TEXT | | 初期値（文字列形式で保存） |
| `is_active` | BOOL | DEFAULT true | 有効/無効フラグ |

## 4. 運用フロー

### 4.1 初期データの投入 (Migration)
1.  `data/constants.txt`, `variables.txt`, `transforms.txt` をパースする。
2.  各行を `char` (記号), `name` (識別子), `description` (説明) に分割する。
3.  カテゴリ（A〜E）を自動判定し、DBへ `UPSERT` する。

### 4.2 新規登録
1.  Symbol_Agentは新たな提案を受け取ると、DB上の `char` の最大値を確認する。
2.  次のコードポイントを算出し、新規レコードを作成する。

### 4.3 整合性チェック
*   定期的にテキストファイルとDBの内容を照合するスクリプトを実行する。
*   不一致がある場合は、DBを正（Master）とし、テキストファイルを更新して同期する。

## 5. バックアップと復旧
*   Supabaseの自動バックアップ機能を利用する。
*   週次で `symbols` テーブルの内容をCSVとしてエクスポートし、`data_backup/` に保存する。
