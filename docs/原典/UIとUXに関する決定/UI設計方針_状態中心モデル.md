# UI/UX設計方針：状態中心モデル

> **注意**: 本ドキュメントはバージョン2以降で実装予定の機能を記述しています。
> バージョン1では、タイムラインUIや状態の配置機能は実装されません。
> v1の範囲については `docs/データモデルに関する決定3/バージョン１の提案.txt` を参照してください。

---

## 1. 基本思想（v2以降）
- **状態中心設計**: ユーザーは「何をするか（タスク）」ではなく「どのような状態でありたいか」のみを指定する。
- **システムによる自動補完**: タスクの選択、測定のタイミング、チェックリストの提示などは、選択された状態に基づいてシステムが自動的に決定する。
- **入力負荷の最小化**: ユーザーの操作は状態の配置と、実行時のシンプルなYes/No確認に限定する。

## 2. ユーザーインターフェース (UI)（v2以降）

### タイムライン (Timeline)
- **DAWライクな表示**: 音楽制作ソフト（DAW）のような横スクロール型の並列トラック表示を採用。
- **トラック構成**: 以下の3トラックを並列に配置。
    1. **ユーザー状態**（最優先）: 生理的・心理的モード（例：集中、リラックス、睡眠）。
    2. **環境状態**: 場の物理的特性（例：ゼロ・フリクション、コグニティブ・クリアランス）。
    3. **社会的状態**: 対人関係モード（例：遮断、交流、協力）。
- **操作**: デベロッパーが用意した「状態プリセット」をドラッグ＆ドロップ（またはタップ）で配置。

### 状態の可視化
- **簡易アイコン/色相**: 複雑なパラメータを単一のアイコンや色相（緑＝良好、赤＝乖離など）で抽象化して表示。
- **詳細の段階的開示**: 通常は簡易表示とし、タップ/クリック時のみ詳細パラメータ（脈拍、室温など）を展開。

## 3. インタラクションフロー（v2以降）

### 計画段階
1. ユーザーがタイムライン上に「8:00〜10:00: 集中状態」を配置。
2. システムが自動的に環境状態（コグニティブ・クリアランス）と社会的状態（遮断）を補完（ユーザーによる変更も可）。
3. システム内部で「測定モード」や必要な「タスク（呼吸法など）」が裏でスケジュールされる。

### 実行段階
1. **通知**: 状態開始時刻に「集中状態の時間です」と通知（リマインダーではない）。
2. **確認**: Watch/スマホで「現在、この状態ですか？」とYes/Noで確認。
    - **Yes**: そのまま継続。
    - **No**: システムが介入（「深呼吸しましょう」「少し歩きましょう」等の代替行動提案）。
3. **記録**: 生体データ（HealthKit）はバックグラウンドで自動記録。手動入力は最小限。

## 4. データモデルの解釈変更（v2以降）
- **「予定」の統合**: 会議などの外部予定は「その件を想起している状態」として状態オブジェクト化する。
- **「測定」の統合**: 測定時間は「測定を行っている状態」として扱う。
- **「リマインダー」の廃止**: タスク単位の通知は廃止し、状態遷移の通知に一本化。

## 5. プラットフォーム展開（v2以降）
- **iOS (Main UI)**: タイムラインの閲覧・編集、詳細情報の確認。
- **watchOS (Sensor & Action)**: 生体データの測定、通知の受信、Yes/Noのクイック入力。
- **Web (Dashboard)**: PCでの大画面閲覧、デベロッパーによるマスターデータ管理。
