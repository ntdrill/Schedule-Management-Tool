# バージョン別機能スコープ（Version Scope）

## 目的

本ドキュメントは、v1（MVP）とv2以降の機能境界を明確化し、実装範囲の混乱を防止することを目的としています。

---

## 1. バージョン戦略の概要

本プロジェクトは明確なバージョン境界を持ち、段階的に機能を拡張していきます。

| バージョン | 位置づけ | コンセプト |
|:---|:---|:---|
| **v1** | MVP（最小実用製品） | 「測定と介入の記録」に特化したロガー |
| **v2以降** | 拡張版 | 「状態中心設計」に基づくスケジューリングシステム |

### v1のコンセプト

カレンダーによる未来の計画（配置）を行わず、**「今」の測定モードON/OFF**と、**「今」行った対処行動の記録・評価**に集中する。

### v2以降のコンセプト

ユーザーは「何をするか（タスク）」ではなく「どのような状態でありたいか」のみを指定し、システムが自動的に補完する**状態中心設計**へ移行。

## 2. v1 実装機能（詳細）

### A. 測定モード管理 (Measurement Control)

| 項目 | 内容 |
|:---|:---|
| **機能** | 測定状態のON/OFF切り替えスイッチ |
| **ON時** | HealthKit/SwitchBotからのデータ収集をアクティブ化し、バックグラウンドで記録 |
| **OFF時** | データ収集を停止し、バッテリーとリソースを節約 |
| **UI** | Watch/iOS共にメイン画面に大きなトグルボタンを配置 |

### B. 期待状態・状態入力 (State Input)

| 項目 | 内容 |
|:---|:---|
| **機能** | 「現在目指している状態（期待状態）」の選択と、現在の主観状態の記録 |
| **入力方式** | リストから「今のターゲット」を選択（選択しなくても測定は可能） |
| **段階評価** | 数値ではなく段階（例: 1〜5、Good/Bad）で現在の感覚を記録 |

### C. 対処行動と評価 (Action & Evaluation)

| 項目 | 内容 |
|:---|:---|
| **機能** | 対処行動（タスク）の実行記録と評価 |

**フロー**:
1. **Select**: プリセットされた対処行動リストから選択（例：「深呼吸」「パルスシフト」）
2. **Start/Stop**: 開始と終了をタップ（タイムスタンプ記録）
3. **Evaluate**: 終了時に効果と状態変化を段階評価で入力

**目的**: 行動と前後のデータ（センサー値＋主観評価）をセットで保存

### D. データ収集と紐付け (Data Logging)

| データ種別 | 収集内容 |
|:---|:---|
| **客観データ** | 心拍数、室温、湿度（センサー連携） |
| **主観データ** | ユーザーが入力した段階評価 |
| **コンテキスト** | 測定モード状態、選択中の期待状態、実行中の対処行動 |

**出力**: iOSアプリ上で時系列のログまたはグラフとして確認可能

### E. 通知 (Notification)

| 項目 | 内容 |
|:---|:---|
| **方式** | ローカル通知（UserNotifications framework） |
| **トリガー例** | 測定モードONのまま長時間経過した場合の確認、対処行動中の経過時間通知 |

> **Note**: 危篤状態の閾値判定による通知はv2以降で実装予定

---

## 3. v2以降で実装予定の機能（詳細）

### UI/UX拡張

| 機能 | 説明 |
|:---|:---|
| **タイムラインUI** | DAWライクな横スクロール型の並列トラック表示 |
| **状態の配置（スケジューリング）** | 状態プリセットをドラッグ＆ドロップで時間軸に配置 |
| **ドラッグ＆ドロップ操作** | 直感的な状態配置のためのインタラクション |
| **簡易アイコン/色相表示** | 複雑なパラメータを単一のアイコンや色相で抽象化 |
| **詳細の段階的開示** | 通常は簡易表示、タップ時のみ詳細パラメータを展開 |

### 高度な判断・処理

| 機能 | 説明 |
|:---|:---|
| **LLMによる判断・推論** | AIを活用した状態分析と行動提案 |
| **代替タスクの自動算出** | 状態から適切な対処行動を自動提案 |
| **再スケジューリング** | 状態変化に応じた計画の自動調整 |
| **全体エントロピーの計算** | システム全体の秩序/無秩序度の定量化 |

### 状態管理の拡張

| 機能 | 説明 |
|:---|:---|
| **社会的状態の管理** | 対人関係モード（遮断、交流、協力）の追跡 |
| **危篤状態の閾値判定・自動検知** | 生体データに基づく異常状態の自動検出 |
| **危篤状態からのリカバリープラン生成** | 異常状態からの回復支援 |

### データ同期・センサー拡張

| 機能 | 説明 |
|:---|:---|
| **iCloud (CloudKit) によるデバイス間同期** | 複数デバイス間でのデータ共有 |
| **CO2濃度など詳細な環境センサー** | より詳細な環境状態の取得 |

## 5. 技術方針（バージョン共通）

以下の技術方針はv1から採用し、v2以降も継続します。

| 方針 | 説明 |
|:---|:---|
| **Local First** | サーバー不要、データは端末内（SwiftData）に保存 |
| **Watch Centric** | ユーザー状態の測定と簡易入力はWatch単体で完結 |
| **Trigger Sync** (v2以降) | 変化量が大きい時のみ通信、バッテリー節約 |
| **Flexible Sampling** | センサー取得頻度はユーザー設定可能 |

## 6. 開発フェーズ (v1)

v1の開発は以下のフェーズで進行します：

| Phase | 内容 |
|:---|:---|
| **1. Project Setup** | iOS/Watch連携プロジェクト作成、HealthKit/SwiftDataセットアップ |
| **2. Sensor Logic** | バックグラウンドでの心拍・SwitchBotデータ取得ロジック実装 |
| **3. Data Model** | 測定セッション、状態ログ、行動ログのデータモデル定義 |
| **4. Watch UI** | 測定ON/OFFと簡易入力の実装 |
| **5. iOS UI** | ログ閲覧と設定画面の実装 |
