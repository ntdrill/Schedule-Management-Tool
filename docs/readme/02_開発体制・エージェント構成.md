# 開発体制・エージェント構成（Agent Architecture）

本プロジェクトは「**観点の補充**」理論に基づき、マルチエージェントアーキテクチャで開発を進めています。本資料では、各エージェントの役割と相互作用について説明します。

---

## 1. 「観点の補充」とは

### 背景にある課題

実装がうまくいかない原因は「技術力不足」や「時間不足」ではなく、**「文脈（観点）の欠如」**にあるという考えに基づいています。一人の人間がアーキテクチャ・セキュリティ・品質・納期など多数の観点を同時に考慮しようとすると、認知負荷が高すぎてパンクしてしまいます。

### 解決アプローチ

| 概念 | 説明 |
|:---|:---|
| **視点の外在化** | 「1つのエージェント ＝ 1つの専門的な観点」として役割を分割 |
| **線形判断の組み合わせ** | 複雑な非線形の問題を、単純な判断の集合体として処理 |

> **「エージェントを作る ＝ プロジェクトに欠けている『観点』を補充する」**

### 2.2 状態モデル担当

| エージェント名 | パス | 担当観点 | 責任範囲 |

| **Environment_State_Agent** | `Agent_workspace/environment_state_agent` | 環境状態、エントロピー | 環境状態スキーマの定義、掃除タスクによるネゲントロピー計算 |

| **Organization_State_Agent** | `Agent_workspace/organization_state_agent` | 組織論、ペアリング | 組織エントロピーの詳細定義（Social_State_Agentと統合検討中） |

### 2.3 UI/UX担当

| エージェント名 | パス | 担当観点 | 責任範囲 |
|:---|:---|:---|:---|
| **UI_Design_Agent** | `Agent_workspace/ui_design_agent` | UI/UX、可視化 | 状態中心UIの設計、カレンダー表示、状態のグラフィック表現 |

### 2.4 システム基盤担当

| エージェント名 | パス | 担当観点 | 責任範囲 |
|:---|:---|:---|:---|
| **Symbol_Agent** | `Agent_workspace/symbol_agent` | 記号接地、データ構造 | 辞書の管理、概念と実装の紐付け、ID体系の管理、DB管理 |
| **Data_Model_Agent** | `Agent_workspace/data_model_agent` | システム構造設計、形式記述 | 静的スナップショット記述、クラス/関係性の抽出、モデル整合性管理 |
| **Task_Management** | `Agent_workspace/Task_Management` | タスク管理 | 各エージェントからの提案と実行状況の集約 |

## 4. エージェント間の相互作用

### 4.1 タスクフロー

開発タスクは以下の自律的フローで処理されます：

```
1. 提案 (Propose)    → Task_Management/01_Proposals/
   ↓
2. 割り振り (Assign) → Task_Management/02_Active/
   ↓
3. 実行 (Execute)    → 担当エージェントが作業
   ↓
4. 完了 (Complete)   → Task_Management/03_Completed/
```

### 4.2 レイヤー間の連携パターン

| 連携パターン | 説明 |
|:---|:---|
| **状態モデル → UI_Design** | 各状態エージェントが定義したスキーマをUIで可視化 |
| **状態モデル → Symbol** | 状態の概念定義を記号体系に登録 |
| **Symbol → Data_Model** | 記号情報をシステム構造に反映 |
| **Agent_Manager → 全エージェント** | タスク割り振り|

### 4.3 情報フローの例

```
┌──────────────────┐    スキーマ定義     ┌──────────────┐
│ User_State_Agent │ ─────────────────► │ Symbol_Agent │
└──────────────────┘                    └──────┬───────┘
                                               │
                                          記号登録
                                               │
                                               ▼
┌──────────────────┐    可視化要件      ┌──────────────────┐
│  UI_Design_Agent │ ◄────────────────  │ Data_Model_Agent │
└──────────────────┘                    └──────────────────┘
```

## 5. エージェント標準ディレクトリ構造

各エージェントは以下の標準構造を持ちます：

```
Agent_workspace/{agent_name}/
├── docs/           # ドキュメント、仕様書
├── 業務/           # タスク定義、業務リスト
├── experience/     # 経験・学習の記録（オプション）
└── data/           # データファイル（オプション）
```
