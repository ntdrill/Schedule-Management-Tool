## 資料準拠

情報源: `Agent_workspace/Task_Management/README.md`、`Agent_workspace/Agent_maneger/docs/README.md`

### Agent_workspace/Task_Management

- 目的: プロジェクトの実装タスクを管理するディレクトリ。
- 役割: 各エージェントが自律的にタスクを提案・実行するための中核。
- ディレクトリ構成（実態でも一致を確認）:
  - `01_Proposals/`: 各エージェントの提案を格納。
    - 作成ルール: 誰でも作成可能。
    - ファイル名規則: `proposal_by_[AgentName]_[Subject].txt`
    - 内容: 現状の課題、提案内容、期待される効果。
  - `02_Active/`: Agent_Manager が承認した進行中タスクを格納。
    - 運用ルール: `01_Proposals/` から移動。
    - ファイル内に `## Assignment` セクションを追記し、担当者と期限等を明記。
    - 担当者が進捗をファイルに追記。
  - `03_Completed/`: 完了したタスクのアーカイブ。
    - 完了ルール: 実装とテスト完了後、**進捗管理agent への報告を行ったうえで**移動。
    - 完了報告（成果物リンク、報告ファイル名など）をファイル末尾に追記。
  - `04_Archive/`: フェーズ単位など、長期保管用のアーカイブ束（実態に存在）。
  - `error_report/`: 障害／差戻しの記録（実態に存在）。
- 運用フロー: `Propose -> (Manager Review) -> Active -> (Execute) -> Report to Progress Agent -> Complete`

### Agent_workspace/Agent_maneger

- 目的: 実装エージェントマネージャーのワークスペース。実装フェーズのタスク管理、エージェント編成、設計情報の伝達を担う。
- 理論的背景: 「観点の補充」理論に基づき、必要な視点を個別エージェントに分担させる。
- ワークフロー:
  - `01_Proposals/`（Task_Management 側） → `02_Active/` → 実行と確認 → `03_Completed/`
- 機能:
  - エージェント編成
  - 業務管理（`業務/` でのチケット管理）
  - 情報伝達（`docs/` 内の決定事項の指示）
- ディレクトリ構造（実態と突合済み）:
  - `業務/` — マネジメント業務ログとタスク定義（`01_xxx.txt` 形式）。
  - `docs/` — `agent_list.txt`, `Agent管理.txt`, `観点の補充.txt`, `Agent_Philosophy.md`, `README.md`。
  - `Task_Inbox/` — 受信タスクの一時置き場。
  - `data/` — マネージャ運用データ。
  - `experience/` — エージェント運用の経験ログ。
  - `scripts/` — マネージャ用スクリプト群。
  - `クロック受付/`, `クロックアーカイブ/` — クロック報告の受付／保管。
  - `__init__.py` — Python パッケージ化マーカー。
