# 03_Git履歴管理ルール

## 目的
コミット履歴を整理し、変更追跡を容易にする

## ステータス
予定

---

## 内容

### 1. コミットメッセージ規則

#### 形式
```
[タイプ] 件名

本文（任意）
```

#### タイプ一覧
| タイプ | 用途 |
| :--- | :--- |
| `[Add]` | 新規ファイル・機能の追加 |
| `[Update]` | 既存ファイルの更新 |
| `[Fix]` | 誤りの修正 |
| `[Refactor]` | 構造変更（機能変更なし） |
| `[Doc]` | ドキュメントの追加・更新 |
| `[Agent]` | エージェント関連の変更 |
| `[Schema]` | スキーマ・データ構造の変更 |

#### 例
```
[Add] Symbol_Agent: 記号の割り当て_2.md を追加

新規シンボルの追加案をまとめたドキュメント
```

```
[Fix] v1仕様の誤り修正

Gemini 3.0 Proによる自動生成の誤りを修正
v2以降の機能をv1から除外
```

### 2. コミット粒度
- 1つの論理的な変更単位でコミット
- 複数エージェントにまたがる変更は分割を検討
- 大規模変更は段階的にコミット

### 3. タグ付け（必要に応じて）
- 重要なマイルストーン: `v1.0`, `phase1-complete` など
- リリース候補: `rc-YYYYMMDD`

### 4. ブランチ運用（将来検討）
- 現状: mainブランチのみ
- 将来: feature/[機能名] 形式での開発ブランチ
