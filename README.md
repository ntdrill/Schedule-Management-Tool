# Schedule Management Tool

このリポジトリは、議事録と設計資料に基づいてまとめられたスケジューリング支援ツールのプロトタイプを収録しています。`web/` ディレクトリ内の静的Webアプリケーションをブラウザで開くことで、予定オブジェクトと実行オブジェクトを統合的に確認・更新できます。

## プロジェクト構成

- `web/index.html` — SPAのエントリーポイント。状態エディタ、テンプレート一覧、予定/実行ログ、通知タイムラインで構成されています。
- `web/styles.css` — カードレイアウトとラベル色分けを含むスタイル定義。
- `web/data.js` — タスクテンプレート、状態辞書、初期状態、危篤状態の対応リストなど資料から抽出した初期データを管理します。
- `web/app.js` — 予定生成、前提条件チェック、実行ステータス遷移、評価計算、代替タスク提案、通知ログなどの主要ロジックを実装しています。
- `*.txt` — 設計検討ログ。状態管理、タスクテンプレート、危篤状態検知などの要件が日本語でまとめられています。

## 使い方

1. `web/index.html` をブラウザで開きます。
2. 左ペインの「現在の状態」でユーザー・環境・社会的状態を調整します。変更は自動保存され、前提条件チェックや評価に即時反映されます。
3. 「タスクテンプレート」から予定に追加したいタスクを選び、開始時刻と所要時間を入力してスケジュールします。
4. 「予定と実行」セクションでは、前提条件適合率・期待状態・実行ログを確認しながら、開始/完了/中断/スキップ等のアクションを操作できます。
5. 「通知とログ」には状態スナップショット記録、前提条件スキャン結果、実行ステータス更新などが時系列で記録されます。

## 開発メモ

- 初回ロード時に、設計資料で言及された太極拳、浴室掃除、社会的チェックインのテンプレートを利用したサンプル予定が自動で追加されます。
- `app.js` では、危篤状態とタスクの対応 (`criticalStateRelation`) を優先度ラベルに反映し、緊急タスクの視認性を高めています。
- 代替タスク提案は、資料で定義された前提条件をベースに現在状態との適合率を計算して提示します。
- 実行完了時には期待状態 (After) と実際の状態を比較し、一致率と不一致フィールドを通知ログに保存します。

資料に沿ってさらなる機能拡張（測定モード統合、LLM判定のモック、詳細な状態履歴ビュー等）を行う際の出発点として活用してください。
